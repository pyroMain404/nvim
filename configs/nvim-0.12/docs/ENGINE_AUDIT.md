- **G9** — `plugin/41_git.lua:432` and `after/ftplugin/c.lua:92` — both built a project-scoped `'path'` by reading `vim.o.path`/`vim.bo.path` and prepending to it, but the finding runs deeper than the plan assumed: on Neovim 0.12.5, the FIRST write to a never-locally-set global-local string option (`vim.bo`, `vim.opt_local`, or even the canonical `:setlocal path^=`) from ANY buffer promotes that write into the GLOBAL slot too (measured directly: `vim.o.path` read from an untouched buffer, after a completely unrelated buffer's `:setlocal path^=XXX`, comes back `XXX,...`). So reading `vim.o.path` a second time reads back what the first write already corrupted it to — a second `:setf git` on the same patch buffer, or opening a second C/C++ project in the same session, both grew the entry without bound, and the second bug is session-wide, not confined to one buffer. Fixed with `Config.pristine_path`, a snapshot of `vim.o.path` taken in `init.lua` before any buffer can touch it; both sites build from the snapshot instead of the live option. Verified: three repeated `:setf git` no longer grow the patch buffer's `'path'`; opening two different CMake projects in one session no longer accumulates the first project's include directories into the second's. — fixed

- **G3 / G4** — `plugin/41_git.lua:150-166` (`attach`, inside `diff_sources_at`) ran a blocking `vim.system(...):wait()` for `git show <rev>:./<path>` synchronously inside `attach`, which 'mini.diff' calls for EVERY listed buffer on each `set_diff_ref` — freezing the editor for the length of that call, once per buffer, every time a revision is referenced. Verified against real repository history: a path present in an old revision now attaches with `ref_text` populated (async fetch worked); a path absent from an old revision correctly falls through to the Git index source (`attach` returned `false`), same observable result as before, no blocking call on the common path. — fixed

- **H8** (found during Phase 5 verification) — `plugin/42_format.lua:159-191` (`Config.format.selection`) — relied on `conform.nvim`'s own Visual-selection detection, which computes the selection's end column as `#line - 1` on top of an already end-exclusive `#line` - one column short of the real line end. - **H9** (reported by the user after Phase 5) — `plugin/41_git.lua:483-491` (`show_at_cursor`) — always retried `MiniGit.show_at_cursor()` a second time when the window did not change after the first call, on the theory that a deleted file's missing "after" state was the only way to fail without opening a window.
